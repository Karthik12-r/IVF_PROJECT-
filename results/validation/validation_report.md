## 12. Data Leakage Review
See `data_leakage_report.csv` and `data_leakage_report.md`. The comparison input list excludes `IVF_Success`; no target-encoding companion column or post-outcome field exists in this CSV. The generator uses hand-written feature rules to create the synthetic target: this is not direct target-column leakage, but it makes the target structurally dependent on the features. Model scores therefore measure recovery of the synthetic pattern, not real-world IVF clinical performance.

## 14. Limitations
Statistical outliers are not clinical errors. The CSV is synthetic and generated by hand-written rules; no external clinical reference data was used. Application date fields were identified from schema definitions only; database values were not audited. The existing comparison script was intentionally left unchanged and still reads the raw CSV directly; validation produced a separate copy with the same rows and data values, but is not wired as an automated precondition to model training. Data validation does not establish clinical correctness.

## 15. Conclusion
The CSV passed the performed structural and basic integrity checks with 0 missing cells, 0 exact duplicate rows, 0 range/integrity violations, and 0 invalid target values. Statistical outliers are reported separately. These findings describe data quality only and do not imply clinical validity.
